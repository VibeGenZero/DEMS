# Plugin SDK 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the plugin SDK by registrations read access with a check-in hook, guarded Discord role changes, a member search and plugin badges on the profile, without changing SDK 1.0 behaviour.

**Architecture:** Each new `ctx` part gets its own module in `plugin-sdk/` (`registrations.js`, `members.js`, `profile.js`; roles go into `discord.js`), wired in `plugin-sdk/context.js`. Discord access stays behind helpers in a new `bot/pluginRoles.js`, exported through `bot.js`, with mock twins in `dev/mockBot.js`. The core emits `registration.checkedIn` through `plugin-sdk/coreHooks.js`, and `routes/user.js` merges the badge providers into `GET /api/user/profile`.

**Tech Stack:** Node ≥ 22, Express 5, discord.js, `node:test` + `node:assert/strict`, SQLite in tests (dev mock mode).

**Spec:** `docs/superpowers/specs/2026-11-21-plugin-sdk-1-1-badges-design.md` (Part 1). Branch: `feature/plugin-sdk-1.1`.

## Global Constraints

- SDK 1.0 plugins keep working unchanged; `sdk: 1` stays valid.
- Data only through `firebaseAdmin.js`; filter/sort in memory; no `limit`; dates ISO strings.
- User-facing text (errors, reasons, labels) in German, code/comments/commits/wiki in English.
- Discord calls only in a `bot/` helper behind `if (!state.isReady) return <neutral>` + `try/catch`, exported through `bot.js`, with a logging twin in `dev/mockBot.js`.
- `ctx` passes plain data only (no Discord objects, no `req`/`res`).
- Tests first (TDD), `node:test` + `node:assert/strict`, helpers from `test/helpers.js`.
- No new dependencies.
- Every behaviour change updates its wiki node in the same commit, then `npm run wiki`; `npm test` must stay green (it checks the wiki graph).
- Commit messages: English imperative subject + why in the body, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A check-in that is repeated (already checked in) or taken back emits **no** `registration.checkedIn` — pinned in Task 2.
2. A role edited in Discord after it was chosen (it gains `ManageMessages`) is refused on the next `addRole`/`removeRole`, not only in `listRoles` — pinned in Task 3/4 (guard runs on live data per call).
3. A provider that never settles must not delay `GET /api/user/profile` beyond ~2 s, and one that throws must not hide the other plugins' badges — pinned in Task 6.
4. A plugin badge with markup in `name`/`description` reaches the browser only as data (the core's `renderBadgeList` escapes it) and an `icon` like `bi-x" onclick="` is dropped by validation — pinned in Task 6.
5. A `sdk: 1` plugin declaring `registrations:read` or `discord:roles` is „Ungültig“, not silently granted — pinned in Task 1.
