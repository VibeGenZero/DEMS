# Dev mock mode (dev/) — run without Discord and PostgreSQL

> TL;DR: `npm run dev:mock` (or `docker compose -f compose.dev.yaml up --build`) starts DEMS with `DEV_MOCK=true`: a separate SQLite file with seeded dummy data, a persona login instead of Discord OAuth, and a simulated Discord server whose actions are logged as `[MOCK-DISCORD]`. It refuses to start with `NODE_ENV=production`.

## Behaviour differences to production

- Rate limiters are skipped (`skip: () => IS_MOCK_MODE` in `server.js`).
- Setup mode (#138) never applies: the forced values count as set by `.env`, so on `#system` guild, admin role, announcement channel, `BASE_URL`, thread sync and the reset password `dev` show as „aus .env“. `restartBot` logs `Bot simuliert neu angemeldet`. A privacy policy saved on `#system` gates every persona until they accept it (consent dialog); remove it again with an empty text, or `npm run dev:reset`.
- Reminder DMs from `checkReminders` call the real (not ready) `sendDM` → only "Bot not ready" warnings.
- Dates are relative to the first seed; after a few days the sample events are in the past (and a day after their end the archive scheduler moves them into the archive tab) → `npm run dev:reset` (a dev database seeded before D-04 also needs it once for the banners).
- Check-in invitations (B-07): the scheduler does not send them (bot not ready, internal call). `sendCheckinInvitations` logs `Check-in-Einladung an <member> ("<event>") mit Button „Einchecken“` and sets `checkinInvitedAt`. Seed: in the running event Jonas is already invited, Tom is not — generate a new check-in code as Mori to see Tom's invitation. The button itself is covered by `test/discordCheckin.test.js`.
- Discord server events (B-09): `updateScheduledEvent` / `removeScheduledEvent` / `setScheduledEventStatus` log `Server-Event "<event>" aktualisiert` / `entfernt` / `läuft` / `beendet`; an id starting with `gone` counts as deleted in Discord (answers `'gone'`). Seed: the open event is synced (`scheduled`), the running one `active` — save or cancel the first, end the second as Mori to see the log. The scheduler's status calls use the real, not ready helpers and change nothing.
- Clean-up after the event (B-10): `removeRoleFromMembers` logs `Rolle @<role> von n Mitgliedern entfernt` (with the members), `deleteEventChannels` `Event-Channels für "<event>" gelöscht`. Seed: the running event and the past one hand out „Event-Teilnehmer“ and have channel ids; the archive at start cleans up the past event (channels go, Aylin loses the role, Lena and Tom keep it for the running event), „Jetzt beenden“ on the running event as Mori takes the role from its accepted members.
- Comment ↔ thread sync (B-16): `dev/mockMode.js` sets `DISCORD_THREAD_SYNC=true` unless it is set. `mirrorCommentToThread` logs `Kommentar in Thread "<event>" als „<Name> (Web)“: <text>` and stores a fake `discordMessageId`; `deleteMirroredMessage` logs `Kommentar-Kopie <id> im Thread "<event>" gelöscht`. Seed: the raid (the event with `discordThread`) has a comment from Discord by Kira (chip „Discord“) and Lena's website reply to it. Thread messages, edits and deletions are covered by `test/threadSync.test.js` (fake messages emitted on the client).
- Approval requests (B-06): `sendApprovalRequest` / `closeApprovalRequest` log `Freigabe-Anfrage in #<channel> für <member> ("<event>")` and `Freigabe-Anfrage <id> geschlossen ("<event>"): <result>` and store a fake `approvalMessage`. To try it: as Mori choose "#events" as Freigabe-Kanal in the bot center, register Lena for "Turnier: Arena-Cup" (manual approval with form), then accept or reject her on the website and watch the log. The seed's pending requests have no `approvalMessage` (they were never posted).
- Studio events (local plugin studio): `dev/studioEvents.js` sends debug events to the studio over the fork IPC channel, only with `PLUGIN_STUDIO=1` + `DEV_MOCK=true` + `process.send` (else a no-op, never throws). Types: `dm`, `channel`, `role`, `log` (plugin Discord output and `ctx.log`, an `Error` argument with its stack), `request` (`method`, `path` below `/api/plugins/<id>`, `status`, `ms`, `requestBody`, `responseBody`; `routes/plugins.js` wraps `res.send` only while active), `hook` (`name`, `summary`, `ok`, `error`, on failure `file`/`line`; `plugin-sdk/hooks.js`), `error` (`message`, `where` = `register` | `route` | `hook:<name>`, plus `file`/`line` of the first stack frame inside the plugin folder or, for a `SyntaxError`, of the `<file>:<line>` header Node puts in front; `pluginFrame` in `plugin-sdk/studio.js`, the host tells `hooks.js` the plugin folders via `setHookDirResolver`) and `lifecycle` (`status` = the new `runtime` value, sent only when it changes; `plugin-sdk/host.js`). Strings are cut at 10 kB. With `PLUGIN_STUDIO=1` and an IPC channel, `dev/start.js` calls `exitOnDisconnect()`: DEMS exits when the studio drops the channel, so a closed studio leaves no orphaned child.

The local plugin studio drives this mock mode as its preview child: [plugin-studio](../howto/plugin-studio.md).
