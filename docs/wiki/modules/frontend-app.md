# public/js — SPA modules and function map

> TL;DR: The SPA is native ES modules without a build step: `public/js/main.js` imports one module per area (`core/`, `events/`, `polls/`, `admin/`, `pages/`, each ≤ ~500 lines). Values several modules share live in `state` (`core/state.js`). A hash router (`handleRoute`) shows one `<section class="app-section">` at a time; every section has a `show*Section()` loader that fetches the REST API and renders HTML strings. Find the module below and open only that file.

## Boot sequence

0. Before any stylesheet, the classic script `public/theme-boot.js` sets `data-bs-theme` on `<html>`: `localStorage.dems_theme` `light`/`dark` as stored, anything else (`system`, missing, blocked storage) from `prefers-color-scheme`. It repeats `resolveTheme()` of `core/theme.js` because modules run after the first paint; `test/theme.test.js` keeps both equal.
1. `main.js` calls `initActions(document)` and starts the motion hooks in their own `DOMContentLoaded` listener (`onThemeChange(refreshStyleguideTokens)`, `initTheme`, `initDialogMotion`, `initCardFlight`, `initTabGlider`); then come the startup listeners in the old order: `DOMContentLoaded` #1 → boot animation (`runBootAnimation`, GSAP) or skip if `localStorage.dems_boot_ts` is <24 h old → `finishLoading()`.
2. `finishLoading()` → `fetchCSRFToken()` → `loadServerInfo()` (server name, guild id, `window.DEBUG_MODE`) → `checkSetupMode()` (`pages/setup.js`, #138: `GET /api/setup/status`; while DEMS is not set up the setup wizard takes over the page, the navbar is hidden and the boot stops here) → show `?error=` message → `checkAuth()` → `checkMaintenanceStatus()` → `restorePendingRoute()` → `handleRoute()` + `hashchange` listener.
3. `DOMContentLoaded` #2 ("Initialization") → `checkUpdates()` only. Login state comes from `checkAuth()` alone: `/auth/me` clears `isNewUser` on its first read, so a second request at startup would swallow the welcome dialog.
4. `DOMContentLoaded` #3 → click listener of `#info-show-data-btn` (`showUserData`).

Module scripts run like `defer`, before `DOMContentLoaded`, so the order is the same as with the old classic script. The vendored libraries (`bootstrap`, `gsap`, `marked`, `DOMPurify`, `EasyMDE`, `flatpickr`) stay classic scripts in `public/vendor/`; modules use their globals.

## Router (`handleRoute`)

| Hash | Shows | Guard |
|---|---|---|
| `#events` (default) | `showEventsSection()` | login required |
| `#event/<id>` | `showEventDetail(id)` | login required |
| `#polls` | `showPollsSection()` | login required |
| `#poll/<id>` | `showPollDetail(id)` (also remembered as pending route before the login) | login required |
| `#events/<id>` (old Discord links) | rewritten to `#event/<id>` with `history.replaceState` | login required |
| `#profile` | `showProfileSection()` | login required |
| `#admin` | `showAdminSection()` | `state.currentUser.isAdmin` |
| `#members` | `showMembersSection()` (W-15) | `state.currentUser.isAdmin` |
| `#insights` | `showInsightsSection()` (W-14; the navbar marks "Admin") | `state.currentUser.isAdmin` |
| `#event-editor/new`, `#event-editor/<eventId>` | `showEventEditor(param)` (the navbar marks "Admin") | `state.currentUser.isAdmin` |
| `#system`, `#system/<category>` | `showSystemSection(param)` (#138; the navbar marks "Admin"; categories `overview` (default, also for an unknown one), `discord`, `server`, `security`, `ai`, `privacy`) | `state.currentUser.isAdmin` |
| `#member/<id>` | `showMemberDetail(id)` (W-15; the navbar marks "Mitglieder") | `state.currentUser.isAdmin` |
| `#bot-control` | `showBotControlSection()` | `state.currentUser.isAdmin` |
| `#info` | `showInfoSection()` | public |
| `#news` | `showNewsSection()` (D-13; the navbar marks "Info") | public |
| `#privacy` | `showPrivacySection()` (#138; the navbar marks "Info") | public |
| `#debug` | `showDebugSection()` | `window.DEBUG_MODE` |

`handleRoute()` returns the promise of `showEventsSection()`, `showEventDetail()` (the card flight waits for it) and `showSystemSection()`. A page with unsaved input can veto leaving it: `setLeaveGuard(guard)` takes `({ route, param }) => boolean | Promise<boolean>`; while a guard is set and the hash changes, `handleRoute()` asks it. An answer at once leaves the browser history alone: `true` drops the guard and routes on, `false` puts the address of the shown page back (`history.replaceState`). A promise (a confirm dialog) puts the address back while it waits and, on `true`, drops the guard and continues with `location.replace` (no extra history entry; the hash change routes) — so guards answer at once whenever there is nothing to ask, and a page that is shown again sets its guard again. `onRouteLeave(callback)` tells the shown page once, before another route is drawn, that it is left (not on a parameter change within the same route, cannot be vetoed, independent of the guard): pages reset their state there, not in the guard. Before it hides the sections it calls `beginCardClose(route)`: a page opened by a card flight copies itself into the flight layer, and the `#events` case hands `showEventsSection()` to `landCardFlight`. After marking the active navbar link it calls `placeNavMarker()` and `syncNavbarHeight()` (`core/tab-glider.js`: measures the fixed navbar into `--navbar-height` on `<html>`, also on resize and when fonts arrive; sticky bars such as the editor top bar and the settings list sit right below it; the token in `tokens.css` is the start value). A page without its own navbar link marks the link of its list (`NAV_ROUTE`: `member` → `members`, `insights` → `admin`, `system` → `admin`, `news` → `info`, `privacy` → `info`); logged out only `login`, `info` and `news` show.

Logged-out users see `#login-section` for every route except `info`. An event route is stored in `localStorage.dems_pending_route` (15 min); after the login redirect to `#events`, `restorePendingRoute()` opens that event once. Navigate with `navigateTo('event/' + id)`.

## State

`state` from `core/state.js` holds every top-level value that more than one module reads or writes: `currentUser`, `csrfToken`, `serverName`, `cachedRoles`, `countdownTimers`, `descriptionEditor` (EasyMDE), `startDatePicker`/`endDatePicker`/`registrationDeadlinePicker`/`unregisterDeadlinePicker` (Flatpickr; the deadline pickers are optional, W-03), `flyingEventId` (event whose overview card flies; `renderOverview` keeps its place free with `.is-flying`), `detailEventId` (event the detail page shows; `showEventDetail`, `loadDetailParticipants`, `loadComments` and the admin path of `renderCheckinSection` drop answers that arrive for another id), slots: `selectedSlotId`, `selectedAltSlotIds`, polls: `currentPoll`, `pendingPollDecision`, bot control: `botStatusRefreshInterval`, guests: `selectedGuests`.

Module-local values (e.g. `activeCategory`, `currentView`, `calendarEvents`, `calendarMonth`, `currentWizardStep`, `slotPickerSlots`, `pollDeadlinePicker`) stay in their module. `window.DEBUG_MODE`, `window.VERBOSE_LOG`, `window._demsGuildId` stay window properties.

## Rules for changes

- New code: export the function, import what you call (`import { escapeHtml } from '../core/ui.js'`), never assign to an imported binding — shared values go through `state`. Nothing runs on import except registrations; startup code belongs in `main.js`.
- Rendering is string-built HTML: wrap every user value in `escapeHtml(...)`; render Markdown only via `renderMarkdownSafe(...)`; short previews of Markdown (cards, lists) via `escapeHtml(markdownPreview(text))` — cut first, escape after, so no `&amp;` is cut in half.
- Mutating calls: `fetch(url, { method, headers: { 'Content-Type': 'application/json', 'X-CSRF-TOKEN': state.csrfToken }, body })`.
- Show results with `showToast(msg, type)` where `type` is a Bootstrap context (`success`, `danger`, `warning`, `info` → class `text-bg-<type>`; there is no `error`); texts in German. Login/OAuth errors use `showError(msg)` (banner).
- Actions: `data-click="name"` / `data-change` / `data-input` on the element, parameters in `data-*` (escaped with `escapeHtml`), `registerActions({ name: (el) => fn(el.dataset.x) })` at the end of the owning module; the innermost action wins; links get `preventDefault` (a modifier click on a link with a real `href` stays the browser's). Broken images: `data-fallback="hide|initials"`. Built-in: `toggleVisible`, `hide`, `scrollTo` with `data-target`.
- Never write `onclick=` or other inline handlers — the CSP blocks them (`script-src-attr 'none'`) and `test/frontendCsp.test.js` fails. Action names stay literal in the markup (`data-click="saveEvent"`, never `data-click="${name}"`), so the guard test can check that each one is registered.
- Motion: animate through `animateTo` / `animateFromTo` with `SPRING` from `core/motion.js` (they respect "reduce motion"), never a bare `gsap.to` for something that moves; a new `.nav-pills` list calls `glideTabs(container)` after it renders.
- New per-event areas on the event page: clear them in `resetEventDetailAreas`, show them again where they are filled, and drop late answers with `if (state.detailEventId !== eventId) return;` after each `await`.
