# Testing — node:test suites and helpers

> TL;DR: `npm test` runs `node --experimental-vm-modules --disable-warning=ExperimentalWarning --test "test/**/*.test.js"` (built-in runner, no dependencies; the flag lets `loadFrontendModules` load the frontend ES modules with `vm.SourceTextModule`). Server behaviour is tested end-to-end by spawning `server.js` / `dev/start.js` in a child process with a temp SQLite file and driving it with a cookie-aware fetch client that handles CSRF. Single frontend functions run in `node:vm` against a fake DOM (`loadFrontendApp`). Browser smoke tests (Playwright, Chromium only) run separately with `npm run test:e2e`.

## Helpers (`test/helpers.js`)

| Helper | Use |
|---|---|
| `createTempDir(prefix)` | fresh temp directory (SQLite files, cwd for child processes) |
| `cleanEnv(env)` | copy of `process.env` without `DISCORD_*`, `FIREBASE_*`, `DEV_*`, `NODE_ENV`, `SQLITE_PATH`, ... merged with `env` |
| `runNode(code, env)` | run a JS snippet in a fresh process (empty cwd → no `.env` leaks in) |
| `repoPath(rel)` | absolute path as JS string literal for `runNode` snippets |
| `startServer(entry, env)` | spawn `server.js` / `dev/start.js` on a free port, wait for `/healthz`; returns `{ baseUrl, output(), waitForOutput(text), stop() }` |
| `createClient(baseUrl)` | cookie jar; `request(path, opts)` (redirect: manual), `send(method, path, body)` with CSRF token, `cookie(name)` reads the jar (e.g. `connect.sid`) |
| `await loadFrontendApp(routes)` | links the ES modules from `public/js/main.js` with `loadFrontendModules` in a fresh `node:vm` context per call (needs `--experimental-vm-modules`, set by `npm test`); returns `{ app, state, … }` — `app` holds every export of every module, `state` is `core/state.js` (`state.currentUser = persona` logs a user in); fake elements for every `id` in `index.html` and in assigned `innerHTML`, each with the classes of its markup (`isHidden(element)` from `test/helpers.js` tells whether one is hidden: inline `display: none`, or the start state `.is-hidden` without an inline display); `fetch` answers from `routes` (URL → body or `() => body`/promise, else 404); records every `fetch` as `{ url, method, headers, body }`; also returns `element(id)`, `toasts`, `dialogs` (the confirm dialogs shown as `{ text, label, danger }`; the dialog answers at once with the option `confirm`: `true` (default) confirms, `false` dismisses, `'too-early'` clicks the confirm button during the fade-in and dismisses afterwards), `requests`, `location` and `fire(type)` (runs the recorded document listeners) — stubs EasyMDE, flatpickr and `bootstrap.Modal` for the event wizard; `localStorage`/`sessionStorage` stubs (`{ storage }` option for initial entries). Run an action like a click with `app.runAction(name, element)` |

`test/htmlSource.js` reads rendered HTML strings for several frontend tests: `elementsWith(html, attribute)`, `actionTargets(html, action)`, `actionElement(target)` (element double for `app.runAction`) and `assertNoInlineHandlers(html)`.

## Writing a test

- Endpoint behaviour → extend `devServer.test.js` (mock mode, seeded data: ids in `dev/seedData.js` `EVENT_ID`) and log in with `loginAs('<persona>')`.
- In-process module tests: set `process.env` (e.g. `DEV_MOCK`, `DEV_SQLITE_PATH`) and `process.chdir(createTempDir(...))` BEFORE requiring app modules — `firebaseAdmin.js` and the adapter read the environment at require time.
- Frontend function → `loadFrontendApp` (see `eventDetailReset.test.js`); assert `toasts` is empty, because most frontend handlers swallow errors in a `catch` that only shows a toast.
- Each test file runs in its own process (node:test default), so module state does not leak between files.
- Test order inside a file is sequential; some `devServer` tests depend on earlier ones (e.g. draft visibility before "start event").

## Browser smoke tests (`npm run test:e2e`)

- Playwright `@playwright/test` (devDependency, pinned exactly; no install script, so `npm ci` and `npm test` download no browser). Once per machine: `npx playwright install chromium`.
- `playwright.config.js` starts `node dev/start.js` on port 3123 with a fresh temp database (`DEV_SQLITE_PATH` in the OS temp dir) — `data/dems.dev.sqlite` and a running dev server on 3000 stay untouched. Projects: `desktop` 1440×900 and `mobile` 390×844 (touch, folded navigation).
- `e2e/tour.spec.js`: every persona (`admin`, `raider`, `member`, `newbie`) logs in through `/auth/dev-login/<id>` and walks overview → event page → polls → profile → info, admin also admin area and bot control; non-admins do not see the admin nav and are sent back from `#admin`. Plus: raid role picker for the raider vs. "Zugriff eingeschränkt" for the member, logout back to the login page.
- `e2e/styleguide.spec.js`: opens `#debug` as admin (the test server runs with `DEBUG_MODE=true`) and checks that the tokens and all components render, buttons are 32/40/48 px tall, nothing reaches beyond the page width, many tabs scroll sideways on the phone, toast types differ and the confirm dialog opens.
- `e2e/events.spec.js`: the event overview of D-04 — on 390 px at least four cards begin in the first screen, nothing reaches beyond the page width and the category bar scrolls sideways in one line; on 1440 px three columns with the banner above the date tile; the past event is missing and the running one comes first; each persona sees its marker (raider "Angemeldet", member "Warteliste" and "Ausstehend", newbie "Als Gast"); a banner loads and the workshop's missing one leaves the event colour.
- `e2e/admin.spec.js`: the admin table of D-07 — tabs by status with the running event first, "Anmeldungen · 2 offen" and "Archivieren" for the past event; search with hit counts and reset, sorting by a head, both without a second request; a series opens its dates; the menu lies inside the window and above the following rows; a draft of the test is published and deleted through the menu and the confirm dialog (dismissed once); a click on the confirm button during the fade-in followed by "Abbrechen" sends no delete; a cancelled event shows "Abgesagt" in the archive; compact rows on 1440 px, stacked rows without sideways scrolling on 390 px. Tests that change data create their own event, because desktop and phone share the database.
- `e2e/csp.spec.js`: the style policy of D-16 — the header carries `style-src 'self'` and `style-src-attr 'none'`; with scripts switched off every `.is-hidden` element computes to `display: none` (a rule that outranks the class would show here); an admin walks through all pages, the event wizard with editor and date picker and the announce dialog, a member through event page with line-up, poll and profile, and the page reports no `securitypolicyviolation`; a description with a `style` attribute and a `<style>` element reaches the page without them.
- `e2e/updates.spec.js`: the effects of the news dialog — the effect of the current `updates.json` version plays once, the dialog under it stays clickable, the pieces clear themselves and do not return on the next page load; none with `reducedMotion: 'reduce'`; the three styleguide buttons play 60 confetti, 28 power-up and 14 bug pieces whose place comes from the script.
- `e2e/profile.spec.js`: the profile of D-08 — on 1440 px the events stand beside the side column (card, badges, settings) and the first row begins in the first screen; on 390 px one column and nothing reaches beyond the page width; Tom sees every status by start, the history with "Eingecheckt" and "Abgesagt" and reaches the check-in through "Einchecken"; Lena tells both dates of the series apart; Mori sees the slot; Neo gets the empty state with "Events ansehen".
- `e2e/avatars.spec.js`: avatars of D-09 — with Discord's CDN blocked, navbar ("MA" for "Mori (Admin)"), participants, comments, line-up, poll votes, profile card and bot control ("DB") show initials and no image is left; with the CDN answering they are pictures (desktop only).
- `e2e/wizard.spec.js`: the wizard of D-10 (desktop) — a raid built step by step (title and start date checked, MMO-Raid preset), the preview shows card and Discord message with three slot buttons, saving from the preview creates the event; saving a half-done event lands on step 2 and marks steps 2 and 4.
- `e2e/helpers.js`: `loginAs` (skips boot animation and "Neuigkeiten" dialog via `localStorage`, closes the welcome dialog of `newbie`), `navigate` (opens the folded menu on the phone and folds it again afterwards, waiting for the Bootstrap animation — the open menu covers the page and Bootstrap ignores toggles while it animates), `watchErrors` — every test fails on an uncaught page error or a `console.error` (failed resource loads ignored). Chromium reports an inline handler blocked by the CSP (`script-src-attr 'none'`) as such an error, so a forgotten `onclick=` fails every tour step that reaches it; the test "the error watch reports a blocked inline handler" pins that; `waitForDialog(page, selector)` waits until Bootstrap has finished fading a dialog in — use it before clicking a close button, Bootstrap ignores `hide()` while the fade-in runs.
- Not part of `npm test` and not in CI; run it before frontend changes, especially the 3.0 redesign. Output (`test-results/`, `playwright-report/`) is git-ignored.

## Comparing the look before and after (`scripts/style-snapshot.js`)

For CSS refactorings that should not change the look: `node scripts/style-snapshot.js --out data/before.json` starts its own mock server on port 3124, logs in as admin, visits the core pages on 1440 px and 390 px and writes the computed styles of every element (hidden dialogs included, `#debug-section` excluded; running CSS animations are cancelled first). After the change write a second file and run `node scripts/style-snapshot.js --compare data/before.json data/after.json`: one line per property and value pair with the number of elements and sample labels. It records the resting state only (no hover, no focus) and no layout, so also look at the page. Not part of `npm test`; needs `npx playwright install chromium`.

## Commands

```bash
npm test                                    # all suites
npm run test:e2e                            # browser smoke tests (Playwright, needs Chromium once)
node --test test/devServer.test.js          # one file
node --experimental-vm-modules --test test/eventCards.test.js   # one frontend file (needs the flag)
npm run wiki:check                          # wiki only
```

GitLab CI runs the same `npm test` in every pipeline (job `test`); see [ci](ci.md).
